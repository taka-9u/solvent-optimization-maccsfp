# Machine Learning-Guided Solvent Optimization Using MACCS Keys Fingerprints

Code and data accompanying:

> A. Kitamura, Y. Edo, Y. Kondo, H. Morimoto,\* T. Ohshima\*
> *Machine Learning-Guided Solvent Optimization Using MACCS Keys Fingerprints: Application to an Sc(OTf)3-Catalyzed Synthesis of N-Unsubstituted Ketimines*
> *Synlett* **2026**, DOI: [10.1055/xxxx](https://doi.org/10.1055/xxxx)

A partial least squares (PLS) regression model is trained on the MACCS Keys
fingerprints of ten solvents with previously reported experimental yields, and used
to rank-order 29 candidate solvents for an Sc(OTf)3-catalyzed synthesis of
N-unsubstituted ketimines. Experimental validation identified 1,2-dichlorobenzene as
superior to the previously reported optimal solvent (99% vs 72% yield).

### Which files are tracked, and why

| Location | Tracked by git? | Rationale |
|---|---|---|
| `data/` | yes | inputs; the analysis cannot be reproduced without them |
| `qm/qm_nbo_t6311++g/` | yes | raw Gaussian input and output; the primary record of the DFT work |
| `qm/coords.txt` | **yes** | the deposited coordinate/thermochemistry file referred to in the SI |
| `output/` | no | everything here is regenerated by running the notebooks |

`qm/coords.txt` is produced by `7_parse_gaussian.ipynb`, but it is written into `qm/`
rather than into `output/` **because it is part of the deposited dataset** and must
survive in the repository. Do not move it into `output/`, which is excluded from
version control.

Filenames in `qm/qm_nbo_t6311++g/` are the SMILES string of the solvent, so that
`7_parse_gaussian.ipynb` and `6_nbo_analysis.ipynb` can associate each calculation
with the corresponding row of `data/solvent.csv`.

## How to run

```bash
conda env create -f environment.yml
conda activate chemoinfo
python -m ipykernel install --user --name chemoinfo --display-name "Python 3.11 (chemoinfo)"
jupyter lab
```

Run the notebooks in numerical order. `0_fingerprint_and_pls.ipynb` writes
`output/pls_model.joblib`, which notebooks 3, 4 and 5 read. Notebooks 6 and 7 are
independent of the PLS model and only require `qm/qm_nbo_t6311++g/`.

Every notebook resolves paths relative to the repository root, so it can be executed
either from `notebooks/` or from the repository root:

```python
ROOT = Path.cwd().parent if Path.cwd().name == "notebooks" else Path.cwd()
DATA, QM, OUT = ROOT / "data", ROOT / "qm", ROOT / "output"
OUT.mkdir(exist_ok=True)
```

The score and loading plots of Figure 1 are built from the **latent variables (LV1,
LV2) of the PLS model**, obtained from the `x_scores_` and `x_loadings_` attributes of
`PLSRegression`. These are determined using the response variable and are therefore
distinct from the principal components of an unsupervised principal component
analysis.

## Data files

### `data/solvent.csv`

| column | description |
|---|---|
| `name` | solvent name |
| `smiles` | SMILES string, parsed with RDKit |
| `exp_yield` | experimental yield (%); empty for candidate solvents that were not measured |

The ten rows with a value in `exp_yield` constitute the training set (Table 2 of the
main text, taken from *Org. Lett.* **2020**, *22*, 120). The remaining rows are
prediction targets.

### `data/fujinami_benchmark.csv`

The literature benchmark dataset of Fujinami et al. (*Bull. Chem. Soc. Jpn.* **2020**,
*93*, 841), covering the Pd-catalyzed decarbonylative diaryl ether synthesis of
Takise et al. (*J. Am. Chem. Soc.* **2017**, *139*, 3340).

| column | description |
|---|---|
| `name`, `smiles` | solvent identity |
| `exp_yield` | experimental yield (%) reported in ref 9 |
| `pred_ref9` | yield predicted by the physicochemical descriptor model of ref 9 |
| `is_training` | 1 for the five cluster-centroid solvents used to train the model |

The experimental yields and reference predictions are the property of ref 9 and are
reproduced here solely to allow the benchmark of Table 1 to be recomputed.

## Quantum chemical calculations

Geometry optimizations and frequency calculations for the ten training solvents were
performed at the B3LYP/6-311++G(d,p) level with Gaussian 16, Revision C.02, using the
route section

```
# opt freq b3lyp/6-311++g(d,p) pop=nbo geom=connectivity
```

Natural atomic charges were obtained by natural population analysis with the NBO 3.1
module implemented in Gaussian 16. The most negative natural atomic charge of each
solvent is plotted against the experimental yield in Figure 3 of the main text.

`6_nbo_analysis.ipynb` reads the Gaussian output files directly with
[cclib](https://cclib.github.io/) and extracts, for each solvent, the most positive
and most negative natural atomic charge and the HOMO energy.
`7_parse_gaussian.ipynb` collects the optimized Cartesian coordinates and the block of
thermochemical corrections (zero-point, thermal, enthalpy and Gibbs free energy
corrections, and the corresponding sums with the electronic energy) into
`qm/coords.txt`.

## Environment

The results in the paper were obtained with Python 3.11, RDKit 2026.03.5,
scikit-learn 1.7.2 and cclib. MACCS Keys bit definitions are those implemented in
RDKit (`rdkit.Chem.MACCSkeys.smartsPatts`); note that bit 0 is a padding bit that is
always zero, so the 167-bit vector carries 166 informative bits.

## Reproducibility notes

* **Random seed.** The y-randomization test in `1_model_validation.ipynb` uses
  `RANDOM_SEED = 1` with `numpy.random.default_rng`. The mean and standard deviation
  of the permuted errors depend on this seed; the p-values reported in the SI
  (p = 0.032 for three components, p = 0.008 for one component) correspond to this
  setting.
* **Scaler refitting.** Both the descriptor and the response scalers are refitted
  inside every cross-validation fold. Fitting them once on the full dataset leaks
  information about the withheld sample and gives an optimistically low error.
* **Number of latent variables.** Three components are used throughout, including for
  the benchmark model of Table 1.
* **File writing.** `7_parse_gaussian.ipynb` truncates `qm/coords.txt` before writing,
  so that re-running the notebook cannot append duplicate entries.
* **Deterministic file order.** Gaussian output files are iterated in sorted order, so
  that the contents of `qm/coords.txt` and `output/nbo.csv` do not depend on the
  operating system.
